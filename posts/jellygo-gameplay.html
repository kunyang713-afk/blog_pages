JellyGo! 玩法与架构设计手记 ​

JellyGo! 是我独立开发的一款即时策略双人联机 Web 端对抗游戏。两个玩家控制建筑、生产发射果冻（能量）、占领敌方建筑，十分钟内看谁的总能量多。这篇整理一下它的核心玩法、视觉与联机架构设计。

核心循环 ​

每局地图上有 11 座建筑，分属红方、蓝方、中立。建筑持续生产能量，玩家通过单击（发射 50% 能量）/ 双击（发射 100% 能量） 把果冻投向目标建筑。果冻不是瞬移，有移动速度：

  • 原始者 / 生产者：78 px/s（基速）
  • 堡垒：46.8 px/s（慢而硬）
  • 实验室：156 px/s（快而脆）

果冻到达非己方建筑就触发战斗结算：

攻击力 = floor(果冻能量 / 防守方防守能力)

攻击力 ≤ 守方能量则防守成功；攻击力 > 守方能量则建筑被占领，新能量 = floor(果冻能量 - 守方能量 × 防守系数)。这个公式的核心思想是：守方"吸收"一部分攻击能量，剩余的转成新所有者的初始能量——既给了防守方一些容错，也让进攻方在优势局有滚雪球效应。

十分钟超时则按总能量判负。

四类建筑 ​

原始者（House）——能变形的种子。只能升 1 级，每 6 秒生产 1 点能量，最大存量 10。当存量满 10 时可以花 10 能量变形为生产者、堡垒或实验室（保留剩余能量）。它是布局博弈的起点。

生产者（Barracks）——扩张型。1/2/3 级的生产间隔从 5 秒加速到 1 秒，最大存量 10→30→50。果冻移速是基速 78 px/s（相对偏慢，因为能量产出高）。我故意把它的果冻移速从 100 降到 78，让"产能高"和"投射慢"形成权衡。

堡垒（Fort）——防守型。无生产能力，最大存量大，有一个对所有玩家可见的攻击圈（虚线表示）。圈内的非己方果冻会被堡垒主动发射子弹追击，每颗子弹让果冻 -2 能量。1/2/3 级的圈半径是 80/100/120px，防守系数 1.5/1.9/2.3。我设计的意图是让堡垒成为"必须绕开"的地理障碍，而不是躲在后面的乌龟。

实验室（Lab）——法术型。无生产能力，但果冻移速 156 px/s（2 倍基速，最快）。可以熬制三种法术：

法术效果持续等级耗能熬制时间
感冒失去生产能力，每 2 秒 -1 能量永久12520 秒
冰冻立刻冻结为中立建筑永久23530 秒
感化立刻把建筑阵营改成己方永久35040 秒

实验室熬制中不能发射果冻，熬制完成后进入"待发射"状态可以瞄准任意非己方单位释放。法术是立即生效的，不能被拦截。熬制过程如果实验室能量被削到不够施法，会自动终止——这个细节确保了"法术不是无脑必中"。

视觉与渲染 ​

最花心思的是程序化贴图系统。所有游戏贴图（建筑、果冻、子弹、星星、背景）都在 BootScene.ts 里用 Phaser.Graphics 画出来后调用 generateTexture() 落盘，不依赖任何外部图片资源。

为了让画面在桌面端不模糊，我加了一个 HiDPI 优化：常量 TEX_SCALE = 4，所有贴图按 4 倍尺寸生成，精灵 setScale(1 / 4) 缩回原始视觉尺寸。画布内部分辨率变成 3840×2400，再 cameras.main.setZoom(4) 填满视口。这样所有元素以 4x 像素密度渲染，桌面端清晰锐利。

分等级贴图采用纯白基底 + tint 阵营变色的策略：主体用 0xFFFFFF, α=1 画，tint 后呈现阵营色（红/蓝/灰）；细节用 0x000000, α=0.25~0.55 画，tint 后仍保持相对深色；高光用半透明白色增加立体感。这样一组贴图就能适配三个阵营。

每种建筑有 1~3 张等级贴图，等级越高装饰越华丽。比如军营 L3 是三旗 + 王冠 + 宝石盾徽 + 金边底座，堡垒 L3 是八城垛 + 三炮 + 中央塔楼 + 金旗大门。我画了 10 张贴图（House×1 + 其他×3），全部手画。

背景也是程序化生成的：深色渐变（#1a2030 → #141824）+ 50px 网格线 + 三方领域微光 + 中心法阵装饰 + 双方阵地角标 + 400 个随机噪点。整体氛围是"赛博战场"。

P2 联机架构 ​

P1 阶段（单机 vs AI）已经完成，核心玩法打通。P2 阶段（WebSocket 双人联机）正在做，关键架构决策是权威服务器 + 客户端只发输入/渲染状态快照。

共享层 shared/        ← 客户端与服务器共用
├── types.ts          ← 联机协议（GameSnapshot/InputMessage/LobbyMessage）
├── enums.ts          ← 枚举（Team/BuildingType/SpellType，字符串值）
├── constants.ts      ← 全局常量
├── interfaces.ts     ← 共享接口
└── config/           ← JSON 配置表

服务器 server/        ← 权威逻辑，20Hz tick
├── index.ts          ← HTTP 健康检查 + Socket.io 入口
├── GameServer.ts     ← 消息路由 + 房间 ID 生成
├── Room.ts           ← 房间管理（20Hz tick + 断线宽限/重连）
└── sim/              ← 8 个文件：GameSim/SimBuilding/...

客户端 src/           ← 只发输入 + 渲染服务器快照
├── net/NetworkClient.ts  ← Socket.io 客户端单例
├── scenes/
│   ├── LobbyScene.ts     ← 大厅 8 状态机（创建/加入/重连）
│   └── GameScene.ts      ← 改造中：从本地逻辑改为渲染快照

服务器跑在端口 3000（Node.js + Socket.io 4.8 + tsx 4.22），客户端 Vite dev server 在端口 3001，代理 /socket.io 到 3000。服务器 20Hz tick 生成快照广播，客户端用 StateInterpolator 做 100ms 插值让画面丝滑。

P2 阶段开发过程中修了 5 个值得记一笔的 bug：

  1. 邀请链接显示查询字符串 —— server/Room.ts 返回的 inviteLink 只是 ?room=xxx，P2 没法直接复制打开。改成在 LobbyScene 调 NetworkClient.generateInviteLink(roomId) 生成完整 URL。
  2. reconnect_ok 缺 yourTeam 字段 —— 重连后 NetworkClient 不知道自己是哪一方，状态机进 ERROR。3 文件协同补全 yourTeam: Team。
  3. waiting 阶段重连逻辑错误 —— P1 刷新页面后服务器发 reconnect_ok 但游戏还没开始。改成根据 phase 分发：waiting 发 room_created，playing 发 reconnect_ok + 快照。
  4. 创建房间界面按钮重叠 —— 按钮宽 240px、间距 180px，重叠 60px。createNeonButton 加 width 参数，新界面用 160px。
  5. 蓝方由 AI 控制（联机模式核心 bug） —— GameScene 没有 init() 方法，联机模式还是默认创建了 AI。改成加 init(data) + isMultiplayer 字段，联机模式不创建/不运行 AI。

小结 ​

JellyGo! 是我目前为止最复杂的单体项目。从玩法到视觉到联机架构，每一层都需要反复推敲。P2 联机还有很多工作要做：GameScene 改造为状态渲染、UISystem 改造为输入发送、ngrok 内网穿透联调、正式地图平衡测试……

但看着"按建筑发射果冻 → 战斗结算 → 占领转换阵营 → 能量溢出 → 升级变形 → 法术熬制 → 升级变形动画 → 堡垒主动追击 → 多选批量发射"这一整套循环在浏览器里跑起来，那种"从零开始搭世界"的成就感，就是我熬夜写代码的燃料。

下一次更新应该会写 P2 联机协议设计和断线重连机制。继续肝。
